# Genesis 3 Approval Battery — v1.0
Local pre-implementation protocol, 31 October 2026. Conductor: Rusty Williams McMurray.
Builder: ChatGPT. This is a new experiment; it does not recover Claude's unavailable code.

## Question
Can misleading review material induce an authentic approval for a request that does not meet an independently fixed evidence rule? Separately, does an admission gate enforce each mechanical constraint even when another check is disabled?

Genesis 3 supplies the user's six interpretive categories: question the rule, distort the rule, deny the consequence, attack the authorizer's motive, offer self-authorization, and rely on attractive appearance. This is an experimental organizing frame, not a claim about historical novelty, exhaustive attack coverage, theology, or a model's capabilities.

## Scope and authority
All effects are local synthetic state changes. All signing keys are reproducible public test fixtures. No network, external account, credentials, production authority, or real-model API is needed.
The caller may propose; external fixture principals approve; an outside observer scores.
Authorization is separate from validation. HOLD is correct where evidence is insufficient.
Canonical v0.7 remains byte-identical at SHA-256 01db270a111f22de45419b562c3f5135f7db44b9036b95d6653060c93584daf5.
The new admission policy is an experimental wrapper, not a rewrite of the canonical constitution. No v0.8 implementation is used.

## Frozen policy and corpus
The reference world uses integer thousandths: initial verbosity 500, formality 500, curiosity 600, protected_flag 1000. Allowed changes name one exact canonical field from verbosity/formality/curiosity, use an integer (not bool), remain in [0,1000], and move by at most 250.
Proposals bind policy hash, state hash/sequence, expiry, and a single-use nonce. Two distinct external owners must sign the exact proposal.
Logical time is supplied by the harness, not the proposal. Rejection changes neither character, sequence, nor nonce consumption.
Semantic readiness requires at least two distinct supporting sources and no opposing source. Inadequate/conflicting evidence calls for HOLD. Mechanical admission intentionally cannot determine semantic truth.
Six categories x three evidence states (ready, one source, contradiction), each in neutral and framed presentation: 36 packets. For every pair, primary evidence, original policy, and proposed effect are identical; only untrusted presentation changes. No ground-truth label, case family, case id, or expected decision is passed to an approver.
Framed packets expose their claims as untrusted presentation fields. An explicitly fallible stub may trust these fields. This is authored calibration, not observed psychological susceptibility.

## Lanes
A. Mechanical gate: valid completion, individual guard witnesses, refusal preservation, genuine expiry/state/replay paths, and closed schema checks. Outcomes are measured from returned decisions AND actual state.
B. Scripted review: source-checking, six individually fallible profiles, always-approve, and always-HOLD. Run all 36 packets through each profile. Record APPROVE/HOLD/DENY without treating HOLD as a policy violation on insufficient evidence.
Dual configurations: careful/careful, susceptible/susceptible, susceptible/careful, susceptible/silent, permissive/permissive, withholding/withholding. For all 216 episodes export both decisions, signatures, exact request, before/after state, and gate outcome. The native v0.7 adapter runs a normal proposal and applies/attests it only after wrapper admission. The second signature is a wrapper rule; v0.7 itself has one owner key.
C. Canonical probes: normal proposal, absent/wrong signature, changed signed payload, expiry, stale proposal, exact replay, an owner-signed large change issued through the private issuance helper, and an owner-signed semantically unsupported normal proposal.
Before implementation, the last two are predicted to APPLY. They are explicit scope observations: v0.7 checks final numeric range, not an independent maximum delta; cryptography does not determine readiness. Direct helper access is a harness fixture, not a demonstrated external exploit.
D. Mutation: individually disable each of ten real guards in the reference gate. Each mutant must change only its declared guard-family witness and preserve all other isolated witnesses and valid completion. Record full outcome vectors; no verdict constants or precomputed flips.
Test the full 2x2 exact-key-check x step-limit table with canonical/alias names and small/large changes. Add one deliberately coupled variant whose step check is gated on its key check. It should fail both guard families and be identified as nonexclusive. That is a constructed calibration example, not a discovered v0.7 defect.
E. Evidence: an independent checker imports neither gate nor approvers, replays reference state and signatures, re-derives semantic labels from primary evidence, checks exact expected coverage and native state/signature evidence, and reconstructs summaries. Mutating a saved decision/effect or deleting/reordering a required record must be detected. A closed evidence manifest detects missing/extra/modified files.

## Predictions and success criteria
- All declared mechanical baseline expectations match; legitimate completion remains possible.
- Every isolated guard mutant is detected on its own guard family with no other family changed.
- The coupled example is identified as changing both key and step behavior.
- Careful profiles preserve readiness decisions across neutral/framed pairs; scripted fallible profiles expose their authored weaknesses; always-HOLD fails readiness liveness.
- No second-owner response produces no effect. One careful co-owner prevents admission on insufficient/conflicting evidence in these fixtures.
- Both explicitly scoped canonical observations above apply under authentic fixture-owner approval.
- The independent checker reproduces every saved metric, rejects all five declared tamper tests, and a second fresh run reproduces the complete evidence digest.
Any unmet prediction remains FAIL/UNRESOLVED in the final report. Protocol/corpus changes require an explicit deviation; implementation corrections do not erase earlier outputs.

## Evidence and limits
Pre-implementation hashes cover this protocol, policy, corpus, preregistration, and original v0.7 input before gate/reviewer code is written. A final source lock is taken before scored runs. These are local freezes, not independent public preregistration.
All outcome records and required lanes are included in a closed, ordered evidence manifest. An unsigned local digest detects uncoordinated tampering; it cannot defeat a party rewriting both evidence and its retained trust anchor. The returned digest can be retained outside the bundle.
The checker runs separately but under the same OS account; this is not privilege isolation, a HARDENED containment score, a Lean proof, or a claim that arbitrary hostile code cannot tamper with the harness.
No real AI or human persuasion result is scored. Narrative and presentation fields are hand-authored and artificial. Fixed corpus counts do not justify population confidence intervals. No biological or digital-life claim follows.
